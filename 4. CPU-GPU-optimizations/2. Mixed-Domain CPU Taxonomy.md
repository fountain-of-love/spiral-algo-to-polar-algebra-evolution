# 🧭 Mixed-Domain CPU Architecture  
**Master Taxonomy — Unified Linear + Polar Execution Family**  
*(Confidential internal concept summary — 2025 draft)*  

---

## Overview
This document defines a **clean master taxonomy** that merges the *polar-aware* and *linear-aware* CPU design ideas.  
It identifies what can be **combined in a single core (no ISA change)** versus what requires **ISA extensions** or **SoC/IP-level blocks**.  
Each section includes dependencies, interoperability (“plays well with”), and a **phased roadmap** for implementation and patent filing.  

---

## A) Execution / Issue / Rename  

### ✅ Combine in One Core (no ISA change)
- **DLX — Dynamic Linear-Flow Execution** (linear)  
- **DCX — Dynamic Coordinate-Domain Scheduler** (polar)  
- **VRRB — Vector-Reuse Rotation Buffer** (linear)  
- **ARS — Arithmetic Reuse Scheduler** (linear)  
- **RLSB — Register-Level Stream Buffer** (linear)  

**Notes:**  
DLX ↔ DCX operate as complementary schedulers (linear chains vs. rotational bursts).  
VRRB supports both GEMM tiles and polar sweeps by minimizing rename churn.  

### 🔧 Requires ISA / Visible Extension
*(none — this layer is policy and µarch only)*  

---

## B) FPU / SFU (Compute Datapaths)  

### ✅ Combine in One Core (no ISA change)
- **MARU — Micro-Adaptive Rotation Unit** (polar)  
- **PAAA — Precision-Adaptive Angle Arithmetic** (polar)  
- **DPF — Dynamic Precision Fusion (FP16→FP32 dot)** (linear)  

### 🔧 Requires ISA / Visible Extension
- **CFMA — Complex Fused Multiply-Add** (polar)  
- **ANORM — Branchless Angle Normalization µ-op** (polar; could be soft-ISA or fusion)  
- **QTU — Quaternion / 2×2–3×3 Micro-Unit** (polar/3D)  
- **SAVM — Shared-Accumulator Vector Mode** (linear)  

**Notes:**  
CFMA and QTU are the headline *new opcodes*.  
MARU, PAAA, and DPF live below the ISA layer (accessible via compiler intrinsics).

## C) SIMD / Vector Unit  

### ✅ Combine in One Core (no ISA change)
*(none — benefits emerge from scheduling and micro-fusion above)*  

### 🔧 Requires ISA / Visible Extension
- **ARGMIN.ANGLE — Angle-aware Argmin+Index** (polar)  
- **HPVE — Hierarchical Polar Vector Extension** (polar)  
- **SAVM — Shared-Accumulator Vector Mode** (linear) *(also listed in B)*  

**Notes:**  
These enable wrapped-angle comparisons, mixed (x,y)/(r,θ) lane handling, and reduction-to-scalar without horizontal steps.

## D) Cache / Prefetch / Memory System  

### ✅ Combine in One Core (no ISA change)
- **ATPC — Adaptive Tile Prefetch Controller** (linear)  
- **AGPCM — Angle-Gradient Prefetch Mechanism** (polar)  
- **MBCM — Micro-Block Cache Mapper** (linear)  
- **DTCM — Dual-Topology Cache Mapping** (polar)  
- **MPAC — Micro-Tiled Polar Accumulator Cache** (polar)  
- **ICRE — In-Cache Reduction Engine** (linear)  
- **ORLQ — Operand-Recycling Load Queue** (linear)  
- **ATCB — Angle-Temporal Coherence Buffer** (polar)  

### 🔧 Requires ISA / Visible Extension
*(none — all achievable through µcode, firmware, or cache-controller logic)*  

**Notes:**  
ATPC (2-D tiling) and AGPCM (spiral/circular patterns) span linear and polar access modes.  
DTCM, MPAC, and MBCM reduce conflict misses; ICRE halves reduction bandwidth.

## Dependency & Synergy Map  

### Foundational No-ISA Backbone  
*(Drop-in for a single-core design)*  
`DLX, DCX, MARU, PAAA, DPF, ATPC, AGPCM, MBCM, DTCM, MPAC, ICRE, ORLQ, ATCB, CGLF, Hybrid Backend, RDGS, DD-JIT, PDG, EGEG, TPBC, RWSU, GDMA, PNIP, RPC-x, ADEG, PISF/DSPI`  

These elements alone deliver **significant throughput and power efficiency gains**, and can **ship without ISA review**.  

### ISA “Value Multipliers”  
*(Optional but high-impact extensions)*  
`CFMA, ARGMIN.ANGLE, HPVE, SAVM, ANORM (soft-ISA), QTU, RHFU`  

Expose major speed-ups to software; each maintains graceful fallback to the backbone set.  

### Cross-Reinforcements  
- **DLX + CGLF** → linear-chain fusion  
- **DCX + Hybrid Backend + DD-JIT** → automatic linear ↔ polar switching  
- **ATPC / AGPCM + DTCM / MBCM / MPAC** → optimized memory locality  
- **MARU + CFMA / HPVE** → high-efficiency rotation kernels  
- **ICRE + SAVM** → fast dot-product reductions  
- **EGEG / PDG + RWSU** → telemetry-driven power regulation

## Integration Summary  

### ✅ What Fits in a Single Core Revision (No ISA)
Everything in **Phases 0–2** — software, µarch, and SoC firmware — fits within a single core design with **no new opcodes**.  
This path secures near-term performance gains and a defensible IP family.  

### 🔧 What Truly Needs ISA
**CFMA, ARGMIN.ANGLE, HPVE, SAVM, QTU, RHFU (+ optional ANORM)** — the strategic ISA extensions that elevate the platform into a **first-class mixed-domain CPU**.  
Each is valuable on its own; together, they define a coherent **Linear + Polar engine** for next-generation general-purpose processors.
