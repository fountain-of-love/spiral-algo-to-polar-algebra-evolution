# 🧭 Mixed-Domain CPU Architecture  
**Executive Brief — Linear + Polar Optimization Family**  
*(Confidential internal concept summary — 2025 draft)*  

---

## 1. Purpose
Define a unified CPU improvement roadmap that accelerates both **linear-algebra** and **polar/rotational** workloads **without increasing transistor count**, while positioning **optional ISA extensions** for long-term differentiation.

---

## 2. Core Idea
Current CPUs are optimized for **linear vector math** (dot products, FMAs).  
Modern workloads — geometry, routing, robotics, simulation, AI kernels — combine **linear and rotational flows**.  

We introduce a **mixed-domain execution model** able to natively sustain both:

- **Linear-aware path:** streaming, tile, and reuse coherence for matrix/dot workloads.  
- **Polar-aware path:** rotation, angle, and circular-access coherence for geometric workloads.  

---

## 3. Design Philosophy
- ♻️ **No new silicon budget** — all baseline gains achieved by micro-architectural choreography, caching policy, and firmware logic.  
- ⚙️ **ISA-optional uplift** — a compact set of opcodes (*CFMA, ARGMIN.ANGLE, HPVE, etc.*) can later expose further speed-ups.  
- 🧩 **Compiler-cooperative** — metadata and pattern detection let hardware discover linear or polar chains automatically.  
- 🔄 **Symmetric scalability** — same units accelerate both dense linear-algebra and geometry-aware kernels.
