# ⚙️ Linear-Aware CPU Improvements — Under-Exploited, High-ROI Paths  
*(2025 internal architecture memo — full content preserved)*  

This document maps **linear-algebra–centric CPU optimizations** that do **not** require more transistors—only better micro-architectural coordination, memory choreography, and data reuse.  
Each improvement is novel yet practical, expressed in **5W2H** format, grouped by theme.  
All assume the same silicon budget (architecture reorganization, not die-area growth).  

---

## ⚙️ 1. Dynamic Linear-Flow Execution Unit (DLX)

**What:** A dispatch mode that fuses sequential multiply–add µ-ops (a·b + c·d + e·f …) into streaming dot-product chains without renaming stalls.  
**Why:** Classic OoO cores split linear chains into independent FMAs; DLX maintains accumulator continuity → higher FLOP utilization.  
**Who:** CPU core designers, compiler backends.  
**When:** Decode-time “linear chain” detector.  
**Where:** Between rename and issue queue.  
**How:** Track dependent FMAs; bypass renamer; forward accumulator directly.  
**How-much:** +15–25 % throughput gain on GEMM/BLAS, no area cost.

---

## 🧮 2. Register-Level Stream Buffer (RLSB)

**What:** Logical register-file extension that preloads small contiguous vectors before FPU request.  
**Why:** Reduces load-queue pressure, avoids L1 misses in tight vector loops.  
**Who:** Microarchitecture teams (scalar–vector blends).  
**When:** Rename-to-issue path.  
**Where:** Physical register front-end.  
**How:** Detect stride = 1–2; prefetch next 2–4 elements into small FIFO.  
**How-much:** 10–20 % latency hiding on dense LA with no new ports.

---

## 🧩 3. Arithmetic Reuse Scheduler (ARS)

**What:** Scheduler caching recent scalar products/partial sums, reusing them if operand pairs repeat (common in blocked GEMM).  
**Why:** Avoids recomputation; reduces FPU energy.  
**Who:** Compiler/runtime + hardware co-design.  
**When:** When instruction window sees repeat operands.  
**Where:** Issue logic with tiny associative buffer.  
**How:** Tag µ-ops with operand hashes; short-circuit compute if hit.  
**How-much:** 5–8 % energy saving, minor throughput gain.

---

## 🔄 4. Vector-Reuse Rotation Buffer (VRRB)

**What:** Circular buffer for re-rotating register windows during blocked multiplies—hardware “rolling register rename.”  
**Why:** Cuts renaming + load/store traffic in inner loops.  
**Who:** HPC / embedded CPU teams.  
**When:** Repetitive vector MAC phases.  
**Where:** Register renamer.  
**How:** Maintain N shadow registers cyclically reused.  
**How-much:** Up to 30 % rename-stage power saving.

---

## 🧭 5. Adaptive Tile Prefetch Controller (ATPC)

**What:** Prefetcher learning 2-D block access patterns (GEMM) instead of 1-D strides.  
**Why:** Linear-algebra memory is tiled, not sequential.  
**Who:** Cache-controller designers.  
**When:** Firmware/µ-code layer in L2 prefetcher.  
**Where:** L2/L3 prefetch logic.  
**How:** Detect double-stride in address deltas; prefetch along both axes.  
**How-much:** 20–40 % miss reduction in block GEMM/convolutions.

---

## 🧱 6. Micro-Block Cache Mapper (MBCM)

**What:** Cache indexing that maps contiguous tiles to single cache sets to avoid conflict misses.  
**Why:** Tiled LA suffers destructive A/B/C-block interference.  
**Who:** Cache designers.  
**When:** Replace XOR hash with matrix-aware function.  
**Where:** L1/L2 tag logic.  
**How:** Low-bit mixing keeps tile stride in same set; enabled in “tile mode.”  
**How-much:** +10 % effective cache capacity for GEMM.

---

## 📏 7. Dynamic Precision Fusion (DPF)

**What:** Pipeline dynamically fusing two FP16 multiplies into one FP32 accumulator when operands share scale.  
**Why:** Saves issue bandwidth while preserving precision.  
**Who:** FPU architects.  
**When:** Detect exponent similarity.  
**Where:** FPU front end.  
**How:** Pair two FP16 → compute both products → sum → output FP32.  
**How-much:** 1.5× throughput for mixed-precision LA; no new logic.

---

## 🧮 8. In-Cache Reduction Engine (ICRE)

**What:** Adder tree integrated in cache bank for partial reductions (dot-product sums) during evict.  
**Why:** Bring accumulation closer to data → lower bandwidth.  
**Who:** Cache/memory subsystem designers.  
**When:** Write-back of dirty lines tagged “reducible.”  
**Where:** L1/L2 write-back path.  
**How:** Per-bank 32-bit accumulator sums lines before flush.  
**How-much:** 2× bandwidth reduction in reduction-heavy kernels.

---

## 🔬 9. Operand-Recycling Load Queue (ORLQ)

**What:** Load queue recognizing reused elements (e.g., A[i,k] reused across B[k,j]) and replaying them directly.  
**Why:** Avoids redundant fetch between dependent iterations.  
**Who:** Memory-system engineers.  
**When:** Repeating load addresses (stride = block dim).  
**Where:** Load/store unit.  
**How:** Small associative buffer; forward hits internally.  
**How-much:** 5–10 % memory-traffic reduction.

---

## ⚡ 10. Power-Aware Dot-Product Governor (PDG)

**What:** Runtime policy modulating issue width by linear-chain length (long → wide, short → narrow).  
**Why:** Saves power in dot-product tail stages.  
**Who:** Power-management firmware engineers.  
**When:** µ-code loop predictor.  
**Where:** Front-end power controller.  
**How:** Monitor FMA dependency depth; adjust width dynamically.  
**How-much:** 10–15 % power saving, steady throughput.

---

## 🧠 11. Compiler-Guided Linear Fusion (CGLF)

**What:** Compiler pass marking multiply–add loops with linear-chain hints for DLX/RLSB activation.  
**Why:** Software–hardware bridge for sustained optimization.  
**Who:** Compiler vendors.  
**When:** LLVM/MLIR lowering.  
**Where:** Mid-end optimizer.  
**How:** Detect affine loops; emit metadata flags.  
**How-much:** Unlocks full HW benefit (+20 %).

---

## 🔗 12. Shared-Accumulator Vector Mode (SAVM)

**What:** SIMD mode where lanes accumulate into one shared scalar (auto horizontal reduction).  
**Why:** Removes explicit reduction step for small-dot products.  
**Who:** ISA designers.  
**When:** New vector-instruction flag.  
**Where:** Vector reduction logic.  
**How:** Broadcast accumulator pointer; auto reduce in pipeline.  
**How-much:** 1.3–1.5× faster micro-dots; no silicon overhead.
